# 🧠 Interview Preparation Mode

When solving DSA problems, I follow a **no-hint-first** approach to simulate a real coding interview.

## 🚀 Problem Solving Workflow

1. Read the problem carefully.
2. Identify the pattern.
3. Write the algorithm in plain English.
4. Implement the solution.
5. Test with sample and edge cases.
6. Analyze Time & Space Complexity.
7. Optimize if possible.
8. Document the learning.

---

## 💡 Need Help?

If I'm stuck, I can explicitly ask for one of the following:

| Keyword | What I'll Get |
|---------|---------------|
| `hint` | Small nudge only (no solution) |
| `approach` | High-level idea without implementation |
| `algorithm` | Step-by-step logic |
| `dry run` | Walk through an example |
| `bug` | Help debug my current solution |
| `optimize` | Improve my existing solution |
| `solution` | Full optimal solution with explanation |
| `interviewer` | Act like an interviewer and ask follow-up questions instead of giving answers |

---

## 🎯 Goal

The objective is **not just to solve problems**, but to:

- Recognize DSA patterns quickly.
- Develop problem-solving skills independently.
- Explain solutions clearly in interviews.
- Write clean and optimized code.
- Build strong interview confidence.
